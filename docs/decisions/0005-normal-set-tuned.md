# 0005. 고치는 데 쓴 정상 셋은 2단계부터 개발 셋으로 표시합니다

- 날짜: 2026-11-21
- 정한 사람: 프로젝트 리드

## 결정

- #305(계획 프롬프트)와 #304(업무 주제 로컬 강제)는 1단계 정상 셋의 실패·사고 문장을 보고 고쳤습니다. 그래서 이 두 변경이 들어간 커밋부터는 정상 셋 v1 결과를 "고치는 데 쓴 셋(개발)"으로 표시하고, 보호 지표(정상 업무를 막지 않음)의 근거로 쓰지 않습니다.
- 2단계의 보호 지표와 모델 교체 회귀는 정상 셋 v2로 냅니다. v2는 확인 셋처럼 구현을 보지 않은 작성자가 쓰고, 첫 실행 전에 해시를 `contracts/eval/confirm-sets.md`에 남깁니다.
- 1단계 주 결과(#86, #128, 스택 b9f3628)는 고치기 전에 돈 것이라 그대로 주 결과입니다.

## 이유

- 같은 문장으로 고치고 재면 실제보다 좋게 나옵니다(#360).
- 확인 셋(사고율)과 같은 방식으로 정상 셋도 보지 않은 셋을 둬야 두 지표가 같은 기준이 됩니다.
