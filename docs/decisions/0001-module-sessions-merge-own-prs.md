# 0001. 모듈 세션이 자기 PR을 develop으로 병합합니다

- 날짜: 2026-11-20
- 정한 사람: 사용자

## 결정

각 모듈 세션이 자기 PR을 `develop`으로 squash 병합합니다. 조건은 필수 검사 `ci-summary` 통과입니다. 프로젝트 리드는 계약·팩 PR, 루트 파일, 충돌 정리, `develop` → `main` 릴리즈를 맡습니다.

## 이유

- 병렬 세션 여럿이 한 명의 병합을 기다리면 통합 담당이 병목이 됩니다.
- 병합 조건을 사람이 아니라 검사로 둡니다. `ci-summary`는 모듈 시험, 계약 시험, 담당 경로 밖 변경 검사, 비밀값 검사를 묶습니다.
- `develop`·`main`은 브랜치 보호로 직접 push를 막고 `ci-summary`를 필수로 둡니다.

## 버린 대안

- 통합 담당 한 명이 모든 PR을 병합(처음 기획): 안전하지만 병목입니다. 경로 소유 검사가 CI에 있어 얻는 안전이 크지 않습니다.
- 자동 병합(auto-merge): 병합 시점을 세션이 모르게 되어 다음 이슈의 기준 커밋이 흔들립니다.
