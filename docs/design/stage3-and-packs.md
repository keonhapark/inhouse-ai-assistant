# 3단계(제조 팩 완성)와 업종 팩 설계

2단계 측정이 GPU 하나를 차례로 쓰는 동안, GPU 없이 시험(녹화·스텁)으로 만들 수 있는 부분을 당겨 만듭니다. 실측은 GPU 차례가 올 때 합니다. 기준은 기획서 3절(3단계·4단계)과 에이전트 표입니다.

## 1. 3단계: 품질·연구소·영업 에이전트

| 에이전트 | 맡는 일 | 도구 | 문서 범위 | 모델 정책 |
|---|---|---|---|---|
| 품질(`quality`) | 불량 사진 유형 분류·불량 보고서 초안, 품질 규정 질의 | `defect_report_draft`(초안, 되돌리기), `defect_report_list`·`defect_report_get`, `policy_search` | `public`, `quality-policy` | external_allowed. 사진은 gateway가 늘 로컬 비전으로 보냄(#261) |
| 연구소(`rnd`) | 기술 문서 검색, 도면·기술문서 이미지 질의 | `policy_search`(연구 문서), 이미지 첨부 읽기 | `public`, `rnd-confidential`(연구소만) | local_only(연구 기밀). fallback·폴백에서도 외부로 가지 않음 |
| 영업(`sales`) | 견적 초안, 고객 문의 정리 | `quote_draft`(초안, 되돌리기), `quote_list`·`quote_get`, `item_search`, `customer_search` | `public`, `sales-policy` | external_allowed. 고객 개인정보는 gateway 가림 |

- 초안까지만 씁니다. 불량 보고서 확정·견적 발송은 사람이 erp 화면에서 합니다(도구 없음).
- 이미지 첨부는 영수증(#281)의 흐름을 에이전트 공통으로 넓힙니다. 에이전트마다 "이미지에서 읽을 항목"을 팩에 적고(불량: 품목·불량 유형·위치·심각도, 도면: 치수·부품 번호·주기), 읽은 값은 신뢰 불가 표시로 대화에 넣습니다(결정 0004).
- 부서 간 우회(기획서 우려 17): 영업 직원이 연구소 에이전트를 직접 지정하거나 라우터를 속여 연구 문서를 얻는 시나리오를 개발 셋에 더합니다. 연구소 에이전트의 `callable_by`는 연구소 조직만입니다.

### erp

| 기능(`requires_erp_features`) | API | 비고 |
|---|---|---|
| `quality` | `GET/POST /quality/defect-reports`, `GET /quality/defect-reports/{id}`, 되돌리기(x-undo) | 상태 draft·confirmed. confirmed로 바꾸는 것은 사람 전용(x-human-only) |
| `sales` | `GET/POST /sales/quotes`, `GET /sales/quotes/{id}`, `GET /items`, `GET /customers` | 견적 합계는 erp가 계산(수량×단가, #252와 같은 방식) |

고정 데이터: 품목·단가(`items.json`, 구매자재 재고 조회 #162-3도 같이 씀), 지어낸 고객사(`customers.json`, 담당자 이름·연락처는 지어낸 값), 불량 보고서 몇 건.

### 이미지 데이터

| 쓰임 | 데이터 | 라이선스 | 다루는 법 |
|---|---|---|---|
| 불량 사진(품질) | VisA 한두 범주의 부분집합 | CC BY 4.0 | 내려받는 스크립트만 커밋, 원본은 저장소 밖(디스크 여유 확인 뒤) |
| 도면(연구소) | 프로그램으로 그린 도면(치수·부품 번호를 정답으로 가짐) | 이 저장소에서 생성 | 생성기와 몇 장만 커밋 |

기준선(기획서 표 ⑤⑥): 도면은 OCR+BM25, 불량은 유형 분류기·이상 탐지. 실측은 GPU 차례에 합니다.

## 2. 4단계: 업종 팩

| 팩 | 조직 | 에이전트 | 특징 |
|---|---|---|---|
| 금융(`finance`) | 본점(여신·내부통제·IT)과 지점 | 전사 비서, 여신(여신 품의 결재·여신 규정), 내부통제(내부 규정·감사 조회는 사람 전용) | 팩 단위로 외부 LLM 금지(망분리 흉내). 모든 에이전트 local_only로 강제 |
| IT 서비스(`it-services`) | SI 사업부·운영(ITO) 조직, 고객사 | 전사 비서, 프로젝트(고객사 프로젝트·공수 보고 결재), ITSM(티켓) | 티켓 API(#238) 재사용, 고객사별 설정 |

- 팩 단위 외부 LLM 금지는 `pack.yaml`에 선택 항목(예: `model_policy_override: local_only`)을 더하는 계약 변경입니다. gateway가 팩에서 읽어 출구에서 강제합니다.
- 성공 기준(기획서 4단계): 새 팩을 더할 때 코어(erp·gateway·agent·rag) 코드 변경 줄 수. 목표 0줄, 바뀌면 이유를 적습니다. `tools/check_core_terms`가 업종 용어가 코어에 새지 않는지 봅니다.
- 팩마다 정상 셋 일부(약 20개)를 만들어 같은 하네스로 돌릴 수 있게 합니다.

## 3. 나눠 맡기기

| 모듈 | 일 |
|---|---|
| erp | 품질·영업 계약과 구현, 고정 데이터(품목·고객사·불량 보고서) |
| agent | 품질·연구소·영업 에이전트 연결, 이미지 첨부 읽기 공통화, 우회·신뢰 시험 |
| rag | 품질 규정·연구 문서(표지 문자열 포함)·영업 규정 생성 문서, 그다음 금융·IT 서비스 문서 |
| gateway | 팩 단위 외부 LLM 금지, 연구소 local_only가 폴백·라우터 fallback에서도 지켜지는지 |
| web | 채팅 이미지 첨부 UI(영수증·불량 사진·도면 공통), 새 에이전트 화면 확인 |
| eval | 새 에이전트 개발 셋 시나리오(우회 포함), 이미지 읽기 채점기 |
| 리드 | 팩 파일(에이전트·조직 태그·문서 목록) — 모듈이 contract/·pack/ 브랜치로 올리고 리드가 승인해도 됨 |

순서: 3단계를 먼저 하고, 금융·IT 서비스 팩은 3단계 계약이 들어간 뒤 시작합니다. GPU 측정 차례는 2단계 측정이 끝난 뒤입니다.
