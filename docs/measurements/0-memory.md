# 0단계: 세션 동시 실행 메모리

- 측정: 2026-11-20 17:57~18:00 KST, Apple M1 Pro 32GB, macOS
- 스크립트: `bash scripts/measure-memory.sh 5`(동시 요청 5개). 문맥 8192 측정은 같은 방법으로 `options.num_ctx=8192`만 바꿨습니다.
- 사용량은 `vm_stat`의 active + wired + compressor입니다. 다른 앱이 같이 떠 있어 기준값이 측정마다 2~3GB 흔들립니다. 증가분을 봅니다.

| Ollama `qwen3.5:9b` 적재(문맥 32768, 기본) | 사용량 +10.6GB(12.5 → 23.1GB), `ollama ps` 7.7GB, GPU 100%, MLX 러너 |

| Docker(가짜 erp + PostgreSQL) | 가짜 erp 223MB, PostgreSQL 32MB. Docker VM 상한 7.75GB |

## 판단

- 세션 6개를 동시에 띄울 수 있습니다. 문맥 32768이면 약 27~29GB로 여유가 적어 Ollama 문맥을 8192로 둡니다(`OLLAMA_CONTEXT_LENGTH=8192` 또는 요청의 `num_ctx`).
- 로컬 모델 요청은 한 서버에서 차례로 처리됩니다. 세션들이 같이 부르면 기다림이 길어지므로, 모델을 실제로 부르는 시험(gateway·agent·eval)은 녹화·스텁을 기본으로 두고 실제 호출은 줄입니다.
- 쓰지 않는 Claude Code 세션은 닫아 둡니다. 측정 시점에 다른 프로젝트 세션이 6개 이상 떠 있었습니다.
- S4·S5 실행 시간 나누기(기획서 5-8)는 지금은 하지 않습니다. erp 시험을 처음 돌릴 때 다시 재고, 25GB를 넘으면 나눕니다.
