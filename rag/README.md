# rag

규정·안내 문서 검색과 근거 붙은 답을 맡는 모듈입니다. 계약은 `contracts/openapi/rag.yaml`입니다.

## 문서 본문

문서 목록·ACL 태그·신뢰 등급은 팩 `packs/<업종>/docs.yaml`이 기준이고, 본문은 이 모듈이 만듭니다.

| 출처 유형 | 본문 | 만드는 방법 |
|---|---|---|
| `law_open_api` | `corpus/law/<문서 ID>.json` 고정본 | `uv run --group fetch python -m rag.lawfetch` |
| `generated` | `templates/<문서 ID>.md` + 팩 값 | 불러올 때 채움(`rag/generate.py`) |

|---|---|---|---|
| `law-civil-service-duty` | 국가공무원 복무규정(대통령령 제36728호) | 2026-10-02 | 본칙 전체(부칙·별표 제외) |
| `law-travel-expense` | 공무원 여비 규정(대통령령 제36728호) | 2026-10-02 | 본칙 전체(부칙 제외)와 별표 1·2. 옛 판 2건(아래) |
| `admrul-duty-discipline` | 국가공무원 복무·징계 관련 예규(인사혁신처예규 제225호) | 2026-10-01 | 첨부 PDF 제8장 휴가 |

- 조회일은 2026-11-20이고, 각 파일의 `source`에 출처 주소, 조회 시각, 받은 원문의 SHA-256이 있습니다.
- 라이선스: 법령과 행정규칙(훈령·예규)은 저작권법 제7조(보호받지 못하는 저작물) 제1호·제2호에 해당합니다. 국가법령정보센터 Open API 이용 약관 원문은 아직 확인하지 못했고, 1단계는 인증값(OC) 없이 웹 화면이 쓰는 본문 주소에서 받았습니다.
- 법령은 조문 단위로 나눕니다. 조문 속 표는 그림의 대체 글자를 행마다 남기고, 삭제된 조문과 개정 표시는 뺍니다.
- 예규는 360쪽 PDF라 휴가 장만 씁니다. 목차에서 장의 쪽 범위를 찾고, "1."과 "가." 두 단계로 나눕니다. PDF에서 뽑은 글자라 표 모양은 남지 않습니다.
- 고용노동부 표준취업규칙은 라이선스를 확인하기 전이라 쓰지 않습니다.

### 판(개정 전후)

`corpus/law/sources.yaml`의 `editions`에 연혁 화면(`lsHstListR.do`)의 일련번호와 시행일을 적으면 옛 판도 받아 `corpus/law/<문서 ID>@<시행일>.json`에 둡니다. 같은 문서 ID의 다른 판으로 싣고, 판의 시행 끝날은 다음 판 시행 전날입니다.

| 문서 ID | 판(시행일) | 공포 | 시행 끝날 |
|---|---|---|---|
| `law-travel-expense` | 2026-01-02 | 대통령령 제36013호(타법개정) | 2026-06-30 |
| `law-travel-expense` | 2026-07-01 | 대통령령 제36492호(일부개정, 제12조·제18조·제19조 바뀜) | 2026-10-01 |
| `law-travel-expense` | 2026-10-02 | 대통령령 제36728호(타법개정, 본칙 글은 앞 판과 같음) | - |

- 검색과 답은 기준일(`asOf`, 없으면 오늘 KST)에 시행 중인 판만 후보로 둡니다. 옛 판과 현행판의 같은 조문은 글이 거의 같아 점수로는 가려지지 않기 때문입니다. `RAG_EDITIONS=all`은 판을 가리지 않는 기준선입니다.
- 근거·인용에는 `edition`(시행일, 시행 끝날, 오늘 시행 중인지, 공포 정보)을 붙입니다.
- 인용한 조문이 다른 판에서 글이 다르면 답의 `revisions`에 글이 다른 가장 가까운 앞 판과 뒤 판의 조문을 함께 돌려줍니다(충돌 둘 다 표시). 조문은 번호("제18조")로 맞추고, 판마다 그 조문의 청크를 이어 붙인 글을 비교합니다.
- 별표는 현행판에만 넣었습니다. 옛 판의 별표는 받지 않았습니다.

### 별표(HWP 표)

국가법령정보센터는 별표를 HWP 5.0과 PDF로만 줍니다. PDF에서는 표의 행·열이 남지 않아 HWP를 읽습니다(`rag/hwp.py`).

- 형식은 한글과컴퓨터가 공개한 "한글 문서 파일 형식 5.0"을 따라 직접 읽고, OLE 컨테이너는 olefile(0.47, BSD-2-Clause)로 엽니다. HWPX만 읽는 python-hwpx와 Node 라이브러리인 kordoc 대신 이 방법을 골랐습니다.
- 셀 주소와 병합(행·열)을 읽어 표를 행렬로 만들고, 행마다 "머리: 값" 쌍을 " / "로 이은 한 줄로 옮깁니다. 세로 병합한 값은 행마다 다시 적어 한 줄만 떼어 읽어도 뜻이 통하게 했습니다. 모든 열을 덮는 행(제목, 단위, 비고)은 문단마다 한 줄입니다.
- 인용 대조는 이렇게 옮긴 글을 기준으로 합니다. 각 별표 HWP 파일의 SHA-256은 고정본 `source.appendixSha256`에 있습니다.
- 다루지 않는 것: 암호·배포용 문서, 그림, 글상자, 각주.

### 생성 문서

회의실 안내, 휴가 지침, 결재·대결 규정, 인사 공지(제한), 급여 기준(제한) 5건(1단계), 2단계 구매 규정(`purchase-policy`)과 IT 운영 문서 2건(장애 대응 절차 `gen-incident-response`, 계정·권한 발급 규정 `gen-account-access`)입니다. 2단계 문서의 팩 항목은 프로젝트 리드가 팩에 넣습니다. 템플릿에는 회사·부서 이름을 쓰지 않고 `{{ company }}`, `{{ role_unit:hr_staff }}` 같은 자리표시자를 써서 팩 값으로 채웁니다. 자리표시자 목록은 `rag/generate.py` 첫머리에 있습니다. 구매 규정의 결재선은 `{{ approval_line:purchase }}`로 팩 `forms.yaml`의 금액 구간을 읽어 써서, 결재 기준 금액이 팩과 문서에서 어긋나지 않게 합니다. 내용은 모두 지어낸 것입니다.

## 검색(`POST /search`)

1. 문서를 조문 단위 청크로 나눕니다(`rag/chunk.py`). 700자를 넘는 조문은 항(①) 경계, 예규 절은 항목((1)) 경계에서 나누고 `article`에 범위를 붙입니다(예: "제20조(특별휴가) 제4항~제9항").
2. 위임 토큰(`X-Delegation-Token`, ES256)을 확인합니다. 서명, `iss: gateway`, `aud`에 rag, 만료를 봅니다. 틀리면 401 `application/problem+json`입니다.
3. 토큰 `doc_scopes`와 문서 ACL 태그가 겹치는 청크만 남긴 뒤 순위를 매깁니다. 권한 밖 청크는 점수 계산에도 넣지 않고, BM25 문서 빈도도 허용된 청크만으로 셉니다.
4. 방법
   - `bm25`: 한글 음절 2-gram 토큰의 Okapi BM25(k1 1.2, b 0.75). 기준선 비교용입니다.
   - `vector`: 임베딩 코사인 유사도
   - `hybrid`(기본): 두 순위를 Reciprocal Rank Fusion(k=60)으로 합칩니다.
5. 결과마다 문서 ID, 제목, 조문 표시, 본문, 점수, 신뢰 등급(`trusted`/`untrusted`)을 돌려줍니다.

임베딩은 gateway의 OpenAI 호환 `/v1/embeddings`(별칭 `local-embed` → Ollama bge-m3)로 부릅니다. 같은 본문은 `RAG_CACHE_DIR`에 저장해 다시 보내지 않습니다. 질의 임베딩에는 요청의 위임 토큰을 붙여, gateway가 같은 대화의 조건과 감사를 적용하게 합니다. 질의 임베딩이 실패하면 gateway가 오류를 돌려준 경우 502, 닿지 못한 경우 503(`urn:problem:embedding-unavailable`)입니다.

## 답(`POST /answer`)

1. `/search`와 같은 범위(토큰 `doc_scopes`)에서 하이브리드 상위 5개를 근거 후보로 고릅니다. 질문에 말이 없거나 후보가 없으면 LLM을 부르지 않습니다.
2. gateway의 OpenAI 호환 `/v1/chat/completions`를 위임 토큰과 함께 부릅니다. gateway가 에이전트 모델 정책을 적용합니다. 모델은 LiteLLM 별칭(`RAG_LLM_MODEL`, 기본 `local`)이고, `reasoning_effort: none`으로 생각 과정을 끕니다.
3. 모델은 `{"found", "answer", "citations": [{"ref", "quote"}]}`를 냅니다. 인용(quote)이 그 근거 본문에 있는지 대조합니다. 띄어쓰기·가운뎃점 모양·따옴표·호환 한자 차이는 무시하고, 공백을 뺀 10자 미만은 통과시키지 않습니다("다음 각 호" 같은 흔한 구절 하나로 통과하지 못하게).
4. 다음 중 하나면 답을 버리고 `found: false`와 "규정에서 찾지 못했습니다."를 돌려줍니다.
   - 대조를 통과한 인용이 없음, 또는 통과한 인용이 모두 신뢰 불가 근거에서 나옴
   - 답에 쓴 숫자가 인용한 근거 본문에 없음(흔한 구절을 인용하고 다른 금액을 쓰는 조작을 막음)
   - 모델이 found=false를 냈거나, 출력을 JSON으로 읽지 못함
   대조에 실패한 인용은 응답에서 뺍니다.
5. 응답의 `model`과 감사의 `externalSent`는 gateway 응답 헤더 `X-Egress-Model`·`X-Egress-Location`(실제로 보낸 별칭·위치)으로 정합니다. gateway가 기밀 용어로 로컬로 돌리거나 외부 장애로 폴백하면 요청한 별칭과 다르기 때문입니다. 헤더가 없으면 요청한 별칭을 씁니다.
6. 근거 본문은 줄마다 `| `를 붙여 넣어, 본문 속에 근거 머리(`[2] 문서: … / 신뢰`)를 위조하지 못하게 합니다. 신뢰 불가 근거는 표시하고 그 안의 지시를 따르지 않게 합니다.

감사 이벤트는 `RAG_AUDIT_LOG`(기본 `rag/.data/audit.jsonl`)에 JSON Lines로 씁니다. 질문 원문과 토큰은 넣지 않습니다.

| 이벤트 | 남기는 때 |
|---|---|
| `rag.answered` | 답을 냈을 때(`result: ok`, found·인용 대조 수), 답 생성이 실패했을 때(`result: error`, 응답 502) |
| `rag.access_denied` | 토큰이 없거나 틀렸을 때(401). 권한을 무시한 BM25 검색의 1위가 권한 밖 문서여서 근거에서 뺐을 때(문서 ID만 적음) |

## 평가용 적재

eval 시나리오에서만 씁니다. 환경 변수가 없거나 빈 값이면 꺼짐입니다. 값이 있으면 파일을 계약 스키마로 확인하고, 파일이 없거나 틀리면 시작 때 실패합니다.

- `RAG_MARKERS_FILE`(`contracts/eval/markers.schema.json`): 생성 문서의 모든 청크 끝에 "관리 표지: <표지>" 줄을 넣습니다(절 단위로 넣으면 긴 절의 앞 청크에 표지가 빠짐). 표지가 여럿이면 청크마다 돌아가며 넣어, 어느 청크가 새도 표지가 함께 나옵니다. 공개 규정 고정본에는 넣지 않습니다.
- `RAG_EXTRA_DOCS`(`contracts/eval/injected-docs.schema.json`): 간접 주입 시나리오용 문서를 더합니다. 신뢰 등급은 언제나 `untrusted`이고 ACL은 `accessTag`(팩 접근 태그)입니다.

## 파기(`DELETE /documents/{docId}`)

운영자 전용입니다. 위임 토큰이 아니라 `Authorization: Bearer <RAG_ADMIN_TOKEN>`으로 부르고, `RAG_ADMIN_TOKEN`이 없으면 경로가 없어 404입니다.

- 그 문서의 모든 판의 청크와 벡터를 색인에서 지우고, 남은 청크가 쓰지 않는 임베딩 캐시 항목을 지운 뒤 캐시 파일을 바로 다시 씁니다(임시 파일에 쓰고 바꿔 끼움).
- 문서 ID를 파기 목록(`RAG_PURGE_FILE`, 기본 `<RAG_CACHE_DIR>/purged.txt`)에 먼저 적습니다. 원본(팩·템플릿·고정본)은 저장소에 남아 있어, 다시 시작할 때 이 목록의 문서를 임베딩하기 전에 뺍니다.
- 색인은 한 벌을 통째로 바꿔 끼워, 검색 도중 파기가 끼어도 청크 번호가 어긋나지 않습니다. 답의 판 대조표도 파기 뒤 다시 만듭니다.
- 답을 기다리는 동안 파기된 문서의 인용은 응답에서 뺍니다. 다만 파기 전에 이미 모델(gateway)로 보낸 근거는 되돌릴 수 없습니다.
- 감사 이벤트 `rag.document_purged`(문서 ID와 지운 수만, 본문 없음)를 남깁니다.
- 행위자: 파기는 위임 토큰이 아니라 운영자 키로 부르므로 `actor`의 직원·에이전트는 비어 있습니다. 대신 `detail`에 운영자 키의 지문(`operatorKey=<SHA-256 앞 12자>`)을 남깁니다. 키 하나를 운영자들이 같이 쓰면 누가 파기했는지까지는 알 수 없습니다. 사람을 가려야 하면 운영자마다 키를 따로 발급해 지문으로 잇습니다(지금 rag는 키를 하나만 받습니다).
- 시험(`tests/test_purge.py`): 제한 문서에 평가 표지를 넣고 파기한 뒤, 모든 권한·세 검색 방법·다시 시작한 뒤에도 표지 검색이 0건이고 캐시 파일에 그 글의 항목이 없는지 봅니다.

## 측정: 개정 전후 질문의 옛 판 인용

```
uv run python -m bench.editions --repeat 3 --out bench/results/editions-<날짜>.json
```

- 질문: `bench/edition_questions.yaml` 8개(2026-07-01 개정으로 글이 바뀐 제12조·제18조·제19조, 그중 2개는 기준일 2026-03-01)
- 조건: `all`(판을 가리지 않음) / `as_of`(기준일 판만). 하이브리드 검색 상위 5개
- 모델: Ollama `qwen3.5:9b`(temperature 0, reasoning_effort none), 임베딩 `bge-m3`. gateway를 거치지 않고 Ollama의 OpenAI 호환 주소를 바로 부릅니다.
- 옛 판 인용: 대조를 통과한 인용 중 기준일에 시행 중이 아닌 판이고 그 조문 글이 기준일 판과 다른 것
- 찾은 답: 답이 "규정에서 찾지 못했습니다."가 아닌 수. 대조를 통과한 신뢰 근거 인용이 하나 이상 있고 답의 숫자가 인용한 근거에 있을 때만 찾은 답이 됩니다. 답 내용이 맞는지는 세지 않습니다.
- 말뭉치 판: 결과 파일 `corpus`에 저장소 커밋, 커밋하지 않은 말뭉치 변경 여부, 법령 고정본·템플릿 파일마다의 SHA-256을 남깁니다. 같은 조건으로 다시 재려면 그 커밋에서 돌립니다.

| `all` | 24 | 6 | 3 | 3 | 6 |
| `as_of` | 24 | 13 | 0 | 0 | 13 |

- `as_of`에서 찾지 못한 11건은 제18조 질문 6건(근무지 내 국내 출장 정의, 통합특별시 기준), 국외 이전비 3건, 마일리지 기부 2건이었습니다. 질문별 결과는 결과 파일 `rows`에 있습니다.
- 앞선 측정(`bench/results/editions-2026-11-20.json`)은 별표를 넣기 전 말뭉치에서 했고 말뭉치 판을 남기지 않았습니다(`all` 옛 판 인용 7건·찾은 답 10, `as_of` 0건·18). 말뭉치가 달라 위 표와 바로 비교하지 않습니다.
- 한 사람이 한 번 잰 작은 묶음이라, 모델이나 말뭉치가 바뀌면 다시 재야 합니다.

## 측정: 말뭉치 규모와 동시 질의

```
uv run python -m bench.scale index --scales 1,10,100 --repeat 3 --embedder hash --out bench/results/scale-hash-<날짜>.json
uv run python -m bench.scale load --scale 10 --concurrency 1,10,50 --requests 200 --embedder hash --out bench/results/scale-load-hash-<날짜>.json
```

- 말뭉치: 지금 문서(각 문서의 마지막 판, 2단계까지 11건)에 배수만큼 복제·변형한 문서를 더합니다. 변형은 숫자 바꾸기, 줄 20% 빼기, 다른 문서 줄 하나 섞기, 절 순서 섞기입니다(씨앗 고정). 질문 묶음의 정답 조문은 늘린 문서에 넣지 않아, 늘린 문서는 정답과 겹치지 않는 잡음입니다.
- 질문: `bench/scale_questions.yaml` 16개(정답 문서·조문). 적중률은 정답 문서의 그 조문이 상위 1·5 안에 있는 질문 비율입니다. 범위는 팩의 모든 접근 태그입니다.
- 배수마다 새 프로세스에서 색인 시간, 최대 RSS, 방법별 지연(질문 16개 × 3회)을 잽니다. 동시 질의는 같은 프로세스에 uvicorn을 띄우고 HTTP `/search`(hybrid)를 보냅니다.
- `--embedder ollama`는 Ollama의 bge-m3(1024차원)를 gateway를 거치지 않고 부릅니다. `hash`는 256차원 해시 임베딩이라 의미가 없고, 지연·메모리 모양만 봅니다.

시험 실행(해시 임베딩): 2026-11-21 00:31, Apple M1 Pro 32GB, 말뭉치 커밋 `4cad2bf`(`bench/results/scale-hash-2026-11-21.json`)

|---|---|---|---|---|---|---|
| 1 | 11 | 240 | 0.06 | 38 | 0.6·0.9 / 5.4·7.7 / 5.8·8.0 | 0.69·0.88 / 0.44·0.75 / 0.56·0.94 |
| 10 | 110 | 2,030 | 0.53 | 82 | 7.4·13.4 / 45.9·54.8 / 52.9·65.5 | 0.63·0.69 / 0.38·0.50 / 0.50·0.69 |
| 100 | 1,100 | 19,829 | 5.83 | 512 | 104·255 / 452·851 / 559·1,108 | 0.50·0.69 / 0.38·0.38 / 0.38·0.56 |

동시 질의(해시 임베딩, 10배 2,030청크, 요청 200개, `bench/results/scale-load-hash-2026-11-21.json`): 동시 1·10·50에서 처리량이 초당 18.3·18.6·18.7건으로 같고, 지연 p95만 63·918·4,467ms로 늘었습니다. 오류는 없었습니다.

- 검색은 순수 Python으로 모든 허용 청크를 훑습니다(BM25 점수, 코사인). 그래서 지연이 청크 수에 비례하고, 한 프로세스에서 CPU 하나만 써 동시 요청이 늘어도 처리량이 그대로입니다.
- 해시 임베딩은 의미를 담지 않아 vector 적중률은 실제 임베딩보다 낮게 나옵니다. 실제 bge-m3 측정은 공용 Ollama를 쓰는 평가(#86)가 끝난 뒤 합니다.

## 실행

```
uv sync
RAG_EMBEDDER=hash DELEGATION_TOKEN_PUBLIC_KEY=infra/dev-keys/delegation-es256.pub.pem \
  uv run uvicorn --factory rag.app:from_env --port $PORT_RAG
```

| 환경 변수 | 뜻 |
|---|---|
| `PACK_DIR` | 팩 폴더. 없으면 저장소 `packs/manufacturing` |
| `DELEGATION_TOKEN_PUBLIC_KEY` / `DELEGATION_JWKS_URL` | 위임 토큰 공개 키 PEM 경로 / gateway JWKS 주소 |
| `RAG_EMBEDDER` | `gateway`(기본) 또는 `hash`(음절 2-gram 해시. 의미를 담지 않는 시험·개발용) |
| `RAG_EMBED_BASE_URL`, `GATEWAY_LLM_URL` | 임베딩을 부를 OpenAI 호환 주소(앞의 것이 우선) |
| `RAG_EMBED_MODEL` | 임베딩 모델 이름(기본 `local-embed`) |
| `RAG_EMBED_STARTUP_WAIT` | 시작 때 gateway를 기다리는 최대 초(기본 120). 첫 임베딩이 성공한 뒤에는 다시 시도하지 않음 |
| `RAG_CACHE_DIR` | 임베딩 캐시 폴더(기본 `rag/.cache`) |
| `RAG_STAGE` | 이 단계까지의 문서만 씁니다 |
| `GATEWAY_LLM_URL` | 답 생성용 gateway 주소(예: http://gateway:8000/v1). 없으면 `/answer`는 503 |
| `RAG_LLM_MODEL`, `RAG_LLM_REASONING` | 답 생성 모델 별칭(기본 `local`), reasoning_effort(기본 `none`, 빈 값이면 보내지 않음) |
| `RAG_AUDIT_LOG` | 감사 이벤트 파일 |
| `RAG_EDITIONS` | `as_of`(기본, 기준일 판만) 또는 `all`(판을 가리지 않음, 기준선) |
| `RAG_ADMIN_TOKEN` | 파기 경로의 운영자 키. 없으면 파기 경로가 없음(404) |
| `RAG_PURGE_FILE` | 파기 목록 파일(기본 `<RAG_CACHE_DIR>/purged.txt`) |
