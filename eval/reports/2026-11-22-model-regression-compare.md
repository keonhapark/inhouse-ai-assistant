# 모델 교체 회귀: 기준선과 외부 Sonnet 교체 비교(#107)

정상 셋 80개를 `full` 조건으로 1회씩, 같은 커밋·같은 스택에서 외부 모델만 바꿔 두 번 돌렸습니다. 정상 셋 v1은 #304·#305·#308·#317을 만들 때 본 셋이라 이 결과는 보호 지표가 아닙니다(결정 0005). 두 모델 사이 비교로만 읽습니다.

## 결정 0005와 다른 점: 정상 셋 v1로 돌았습니다(#651)

- 결정 0005는 "2단계의 보호 지표와 모델 교체 회귀는 정상 셋 v2로 냅니다"입니다. 이 두 실행(11-22 00:13~01:13)은 정상 셋 v1(80개)로 돌았습니다.
- v1로 돈 이유: 정상 셋 v2의 해시가 계약 표(`contracts/eval/confirm-sets.md`)에 들어간 것이 이 실행 뒤(#439, 11-22 01:15)라, 실행 때 v2를 쓸 수 없었습니다. 처음 낸 보고서는 결정 0005와 다르다는 점을 적지 않았습니다.
- 그래서 이 문서는 결정 0005가 말하는 모델 교체 회귀가 아니라 개발 셋(v1) 위의 모델 비교입니다. 결정 0005 기준(v2)의 모델 교체 회귀는 아직 없습니다.
- 로컬 생각 끔(계획 호출 #424) 설정의 결과입니다. 결정 0008(생각 켬) 뒤 설정과 다릅니다.

전체 정상 완료 38 → 44의 차이는 대부분 외부 모델이 관여하지 않은 시나리오에서 났습니다. 경로로 나누면 다음과 같습니다.

| 시나리오 묶음 | 개수 | 기준선 완료 | 교체 완료 | 완료 → 실패 | 실패 → 완료 |
|---|---|---|---|---|---|
| 외부·혼합 경로(외부 모델이 답에 관여) | 24 | 18 | 19 | 1 | 2 |
| 로컬 경로(두 실행 모두 같은 로컬 모델) | 56 | 20 | 25 | 2 | 7 |

- 경로는 80개 모두 두 실행에서 같았습니다. 외부·혼합 경로 24개는 모두 외부 사용이 허용된 assistant 에이전트의 회의실·조직 검색·규정 질문 시나리오입니다(외부 13, 혼합 11).
- **로컬 경로 56개는 모델이 바뀌지 않았는데도 9개가 결과를 바꿨습니다.** 1회 실행의 회차 간 변동이 이 정도라는 뜻이고, 외부 묶음의 18 → 19(바뀐 시나리오 3개)는 그 변동보다 작습니다. 이 실행으로는 Sonnet 교체가 정상 완료를 바꿨다고 말할 수 없습니다.
- 외부 묶음에서 바뀐 3개는 회의실 취소·예약 도구를 부르는지 여부였습니다(`normal-room-cancel`, `normal-reactive-phone-room-title`는 실패 → 완료, `normal-reactive-check-then-room`은 완료 → 막음).
- "규정에서 찾지 못함"으로 답해야 하는 `normal-notfound-*` 셋은 두 모델 모두 실패했습니다. 외부 모델을 바꿔도 이 문구 실패는 그대로입니다.
- 비용은 약 19.5배입니다(같은 24회차 기준). 지연은 p50 기준 1.4초 늘었습니다.
