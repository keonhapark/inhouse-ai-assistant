# 정적 시안 세 방향 비평 (mixed / ops / assistant)

기준: "실제 회사가 쓸 만한 업무 프로그램이면서 현대적이고 트렌디한 웹 디자인"
근거: 1440×900 PNG 6장, 각 방향 `tokens.css`·`direction.css`, `src/base.css`. 좌표는 PNG 기준 px.

> 이 비평은 첫 시안을 두고 따로 띄운 `UI Designer` 에이전트가 만든 쪽의 설명 없이 그림과 코드만 보고 쓴 것입니다. 뒤에 반영한 것:
> 1 반려 버튼과 승인 확인 상자, 의견을 하단 바로 / 2 목록 아래 "오늘 처리한 결재" 표, 대화 비서형 카드 목록을 표로 / 3 확인 필요 색 띠를 배지와 캡션으로, 정책 줄 배경 제거, 하단 바 배경을 면 색으로 / 4 운영 도구형 선택 행을 중립 회색 + 청록 막대로, 금액·제목 크기 위계 / 5 운영 도구형 결재 상세를 값 먼저로, 두 표 열 폭 맞춤 / 6 대화 비서형 패널 위끝 맞춤, 컨트롤 높이 34px, 중립 그림자 / 7 오른쪽 패널을 가리키던 줄을 요약 행으로 / 8 섞음 카드 폭과 입력창 정렬 / 9 한글 줄바꿈(keep-all), 목록 날짜 형식, 아이콘 14·16px / 10 결재선 현재 단계를 점선 + 시계로.
> 반영하지 않은 것: 탐색 항목 간격 2px(세 방향 공통 리듬을 유지), 상세의 사용일 표기(양식 값 표기는 #556 표시 값 층에서 정함). 4절의 "세 방향 대비가 약하다"는 지적은 비교 페이지에 "고르는 법"(구조와 밀도를 따로 고름)을 더하는 것으로 답했습니다.

## 1. 방향별 평가

### mixed — 업무 도구다움 4 / 5, 현대성 3.5 / 5

가장 좋은 점
1. 셸이 차분하고 정돈돼 있습니다. 연회색 탐색 막대(232px)와 흰 본문을 테두리 한 줄로만 나눠서 최근 B2B SaaS(Linear, Vercel 대시보드) 문법에 가장 가깝습니다. 그런데도 결재함 표(행 40px, 금액 오른쪽 정렬, tnum)는 업무 도구답게 읽힙니다.
2. 채팅 미리보기 카드의 정보 순서가 세 방향 중 가장 좋습니다. 머리(양식·제목·되돌릴 수 있음) → 영수증·읽은 값 → 정책 판정 → 주의 → 결재선 → 남은 시간과 버튼 순서여서 위에서 아래로 한 번 읽으면 결정할 수 있습니다. 금액 20px bold가 카드 안에서 유일한 큰 글이라 초점도 분명합니다.

가장 거슬리는 점
1. **결재 화면 왼쪽 목록 아래 빈 공간**(x 264–814, y 310–900): 표 3줄 아래 화면의 2/3가 비어 있습니다. ops에 있는 "기다린 시간" 열도, "오늘 처리한 결재" 표도 없어서 목록 패널이 할 일 없이 넓습니다.
2. **채팅 미리보기 카드 오른쪽 절반의 빈 공간과 색 띠 3겹**(카드 x 775–1349, y 305–585): 값 열이 x 855–980에서 끝나 오른쪽 370px가 비어 있습니다. 그 아래에 초록 정책 띠(y 443–478), 노랑 주의 띠(y 549–584)가 쌓이고, 결재 화면에서는 파랑 하단 띠까지 더해져 한 카드 안에 옅은 색면이 너무 많습니다. 방향 설명에 쓴 "숫자 오른쪽 정렬 값 대조"도 그림에서는 보이지 않습니다(값이 왼쪽 정렬).
3. **정렬 어긋남 두 곳**: 입력창(x 618–1334)이 대화 열·카드(x 586–1366)보다 좌우 32px씩 안쪽에 있어 아래쪽만 폭이 줄어 보입니다. 에이전트 본문은 "팀장 결 / 재 한 단계로"처럼 낱말 중간에서 줄이 끊깁니다(`word-break: keep-all` 없음).

### ops — 업무 도구다움 4.5 / 5, 현대성 2.5 / 5

가장 좋은 점
1. 결재 화면이 세 방향 중 가장 일을 잘합니다. "기다린 시간" 열과 "오늘 처리한 결재 5건" 표가 있어 팀장이 밀린 정도와 오늘 처리한 일을 한 화면에서 봅니다. 승인/반려 배지가 결과 열에 정렬돼 훑기 쉽습니다.
2. 미리보기 카드의 값이 테두리 있는 2열 표(라벨 회색 칸 + 값 칸)라서 종이 결재 양식에 익숙한 제조사 직원에게 가장 낯설지 않습니다. 대화 목록도 구분선 있는 목록이라 메일함처럼 빨리 훑힙니다.

가장 거슬리는 점
1. **청록 강조색과 승인 초록이 구분되지 않습니다**: 선택 행 배경 `--accent-soft #dff1ef`와 승인 배지 배경 `--st-approved-bg #e3f3e9`가 거의 같은 색입니다. 결재 화면 첫 행(y 172–200, 선택됨)과 아래 표의 "승인" 배지(x 862–905)가 같은 의미로 읽힙니다. 대화 목록의 선택 항목(y 40–97)도 "처리 완료"처럼 보입니다.
2. **위계가 평평합니다**: 상단 제목 h1이 13px(본문과 같은 크기), 결재 상세 제목 "팀 점심 식대"가 15px, 금액 42,000원이 13px bold입니다. 결재에서 가장 중요한 금액이 표 안 다른 값과 같은 크기라 눈이 머물 곳이 없습니다. "오늘 처리한 결재 5건"(y 294) 소제목도 11px 회색이라 표 사이 구분이 약합니다.
3. **결재 상세가 영수증 그림부터 보여 줍니다**(x 977–1424, y 160–388): `doc__body`를 column-reverse로 돌려서 오른쪽 패널 위쪽 230px를 영수증이 차지하고, 값·정책·결재선이 아래로 밀립니다. 그 결과 의견 입력(y 690) 아래부터 하단 바(y 850)까지 160px가 비고, 위쪽은 붐빕니다. "크게 보기"가 영수증 상자 오른쪽 아래 구석에 떨어져 있는 것도 어색합니다. 위아래 두 표의 열 위치도 다릅니다(요청자 x 588 / 567, 금액 x 730 / 735).

### assistant — 업무 도구다움 2.5 / 5, 현대성 3.5 / 5

가장 좋은 점
1. 채팅과 "확인할 일"을 오른쪽 패널로 나눈 구조가 분명합니다. 대화를 계속 이어 가도 실행 전 확인 대상이 오른쪽에 고정돼 있다는 개념이 그림만으로 전달됩니다. 세 방향 중 유일하게 구조가 다른 안입니다.
2. 오른쪽 패널의 금액(28px)과 큰 본문(17px)이 시원해서 한 건을 확인하는 순간에는 가장 읽기 편합니다. 결재 상세의 세로 결재선(x 776–900, y 615–690)도 단계가 늘어날 때 가로형보다 확장성이 좋습니다.

가장 거슬리는 점
1. **결재 목록이 카드라서 훑을 수 없습니다**(x 313–716, y 164–378): 요청자·양식·받은 때가 한 줄 회색 메타 "경비 정산, 오지현, 오늘 12:44"에 섞여 있어 열로 비교할 수 없고, 아래 y 380–888은 통째로 비어 있습니다. 상태 배지(사진에서 읽음, 2단계)도 카드에서 빠졌습니다. 60명 회사 팀장이 하루 수십 건을 보는 화면으로는 가장 약합니다.
2. **셸 가장자리가 서로 맞지 않습니다**: 왼쪽 탐색 막대는 y 12에서, 오른쪽 패널은 y 72에서 시작합니다. 알림 종(x 1384)은 오른쪽 패널 오른쪽 끝(x 1428)과 어긋납니다. 채팅 입력창 아래 끝(y 876)과 패널 아래 끝(y 888)도 다릅니다. 떠 있는 패널 양식은 가장자리가 정확히 맞아야 고급스러워 보이는데, 여기서는 오히려 "덜 끝난" 인상을 줍니다.
3. **공간 낭비와 겹치는 안내**: 탐색 항목 간격이 42px라(`--control-h: 40px`) 메뉴 5개가 y 160–400을 차지합니다. 채팅 가운데 y 360–750은 비어 있고, 본문의 "경비 정산 올리기 · 확인할 일이 오른쪽에 있습니다" 줄(y 312–360)은 오른쪽 패널을 가리키기만 하는 중복 안내입니다. 오른쪽 패널도 결재선 아래 y 650–805가 빕니다. 자두색 강조 + 보랏빛 그림자 + 회보라 바탕이 겹쳐 사내 업무 도구보다 소비자용 AI 앱처럼 보입니다.

## 2. 세 방향 공통 문제

- **타이포 위계**: 결재 화면 안에서 제목 크기가 들쭉날쭉합니다(상단 h1 13–21px, 문서 h2 15–24px, 카드 h3 13–15px). "결재선", "의견" 같은 구역 라벨이 12px 회색 medium(`.doc__section h3`)이라 kv 라벨(dt)보다 오히려 약해서 구역 경계가 보이지 않습니다. 12px 이하 메타 글(시각, 부제, 힌트, 배지)이 화면마다 열 곳 넘게 나와 회색 잔글씨가 많습니다.
- **정렬**: 같은 화면 안에서 왼쪽 기준선이 여러 개입니다. mixed는 입력창과 대화 열, ops는 결재선 라벨(x 721)과 kv 라벨(x 734), 처리한 결재 표와 받은 결재 표의 열, assistant는 셸 위쪽 가장자리가 어긋납니다.
- **간격 리듬**: 세 방향 모두 결재 상세에서 의견 입력과 하단 결정 바 사이에 150px 넘는 빈 칸이 있습니다(`.doc__foot { margin-top: auto }`). 결정 구역(의견 + 버튼)이 둘로 갈라져 보입니다. 미리보기 카드 안쪽 여백도 머리 12px, 본문 16px, 주의 띠 12px처럼 단계 수가 많습니다.
- **색 쓰임**: 한 카드 안에 초록(정책), 노랑(주의), 파랑/보라(하단 바, 진행 중), 보라(로컬 처리) 옅은 색면이 동시에 나옵니다. 표 제목 칸 안에 배지("사진에서 읽음", "2단계")를 넣어 제목 길이에 따라 배지 위치가 흔들리고, 상태 열과 의미가 겹칩니다.
- **아이콘 크기**: 12, 13, 15, 16px이 섞여 있습니다(`.badge .i` 12, `.preview__agent .i`·`.doc__form .i`·`.preview__expire .i` 13, brand 15, 기본 16). 같은 줄에 있는 양식 아이콘과 글자 높이가 맞지 않는 곳이 있습니다(결재 표 "경비 정산" 앞 아이콘).
- **결재선 현재 단계 표시**: 테두리 원 안에 채운 원(`.line__step--current .line__dot`)이라 라디오 버튼처럼 보입니다. 클릭해서 고르는 입력으로 오해할 수 있습니다.
- **결정 버튼**: 결재 하단 바에 **반려 버튼이 없습니다**(세 방향 모두 "취소"와 "승인 확정"만 있음). 의견 칸 안내문은 "반려할 때는 이유를 적어 주세요"인데 반려할 방법이 보이지 않습니다. 결재 화면에서 "취소"는 무엇을 취소하는지도 모호합니다.
- **마감**: 날짜 표기가 섞여 있습니다("11월 20일", "11. 20. 09:15", "2026. 11. 21. 12:44 올림", "오늘 12:44"). 24px 원 안에 두 글자 이니셜("지현", "도윤")이 빽빽합니다. 입력창 힌트 "Enter로 보내고 Shift+Enter로 줄을 바꿉니다"가 늘 보여 잔글씨를 늘립니다. 한글 줄바꿈에 `keep-all`이 없어 낱말이 잘립니다.

## 3. 효과가 큰 수정 (우선순위 순)

1. **결재 하단 바를 "반려 / 승인 확정"으로 바꾸고 의견을 그 안에 넣기 (세 방향)**
   `.doc__foot` 안을 [의견 textarea(1줄, 포커스 시 3줄)] / [확인 문구 · 반려(secondary, 글자색 `--danger`) · 승인 확정(primary)] 2단으로 구성합니다. "취소"는 뺍니다. 의견 칸이 하단 바로 옮겨지므로 의견과 버튼 사이 빈 공간(세 방향 모두 150px 이상)이 함께 사라집니다.

2. **승인함 목록의 빈 공간을 표로 채우기 (mixed, assistant)**
   mixed는 ops처럼 "기다린 시간" 열과 "오늘 처리한 결재" 표를 그대로 가져옵니다. assistant는 카드(`.card-row`)를 버리고 행 48px 표(양식 아이콘 · 제목 · 요청자 · 금액(오른쪽, tnum) · 받은 때)로 바꿉니다. 둥근 모서리와 그림자는 표 바깥 면에만 남기면 방향의 인상은 유지됩니다.

3. **미리보기·결재 카드의 색 띠를 하나로 줄이기 (세 방향)**
   "사진에서 읽은 값" 노랑 띠는 카드 머리 제목 옆 `badge--attention` 하나로 줄이고, 설명 문장은 값 표 아래 12px 회색 캡션으로 둡니다. 정책 판정은 배경을 빼고 아이콘 + 초록 굵은 글 한 줄(mixed는 2px 왼쪽 막대만 남김)로 둡니다. 결재 화면 하단 바 배경은 `--surface`에 위쪽 테두리 1px만 남깁니다. 한 카드 안의 색면이 3개에서 0–1개로 줄어듭니다.

4. **ops의 강조색과 승인색 분리, 위계 복원**
   선택 행 배경을 `--accent-soft` 대신 중립 `#eef0f3`로 바꾸고 청록은 3px 왼쪽 막대에만 씁니다(대화 목록 `.conv.is-active a`도 같게). 금액은 `.dir-ops .kv__row--amount dd { font-size: var(--fs-xl); font-weight: 700 }`, 상단 제목은 `.dir-ops .topbar h1 { font-size: var(--fs-lg) }`, 결재 상세 제목은 `--fs-xl`로 올립니다. 밀도는 그대로 두고 크기 차이만 되살립니다.

5. **ops 결재 상세를 값 먼저로 바꾸기**
   `.dir-ops .doc__body { flex-direction: row; }`로 되돌리고 영수증을 값 표 오른쪽 140px 썸네일로 둡니다(mixed와 같은 배치). 위아래 두 표는 `table-layout: fixed`와 같은 `<colgroup>` 폭(양식 96 / 제목 auto / 요청자 72 / 금액 96 / 시각 96 / 상태 72)을 써서 열을 맞춥니다.

6. **assistant 셸 가장자리 맞추기와 밀도 조정**
   오른쪽 패널을 탐색 막대와 같이 y 12에서 시작하게 하고, 상단 바(제목·알림)는 가운데 열 안에만 둡니다. 알림 종은 가운데 열 오른쪽 끝에 맞추거나 탐색 막대 사용자 줄로 옮깁니다. 입력창 아래 끝을 패널 아래 끝(바닥에서 12px)과 맞춥니다. `--control-h`는 40에서 34px, 탐색 항목 간격은 2px로 줄입니다. 그림자 색조를 `rgb(40 24 80 / …)`에서 중립 회색으로 바꿔 소비자 앱 인상을 덜어냅니다.

7. **assistant 채팅의 중복 안내 줄을 요약 행으로 바꾸기**
   "확인할 일이 오른쪽에 있습니다" 줄을 "경비 정산 올리기 · 42,000원 · 서도윤 팀장 결재 · 확인 필요" 한 줄 요약(금액 tnum, 상태 배지 오른쪽)으로 바꿉니다. 대화 기록에 무엇을 맡겼는지 남고, 오른쪽 패널을 닫아도 맥락이 유지됩니다.

8. **mixed 채팅 카드 폭과 입력창 정렬 맞추기**
   미리보기 카드를 `max-width: 680px`로 줄이고 kv를 `grid-template-columns: 88px 1fr`로 고정해 값 열 오른쪽 빈 공간을 없앱니다. 입력창은 대화 열과 같은 `max-width`·좌우 padding을 써서 왼쪽 끝을 x 586에 맞춥니다.

9. **공통 마감: 줄바꿈·날짜·아이콘 크기**
   `body { word-break: keep-all; overflow-wrap: anywhere; }`를 base.css에 넣습니다. 날짜는 목록 "오늘 12:44 / 어제 17:02 / 11월 20일", 상세 "2026년 11월 21일 12:44" 두 형식으로만 씁니다. 아이콘은 인라인 메타 14px, 본문 16px 두 단계로 정리합니다(12·13·15px 제거).

10. **결재선 현재 단계 점을 입력처럼 보이지 않게 하기 (세 방향)**
    `.line__step--current .line__dot`을 `background: var(--accent-soft); border: 1.5px dashed var(--accent);`에 시계 아이콘 12px로 바꾸고, 이름 옆에 "대기 중" 배지를 붙입니다. 구역 라벨("결재선", "의견")은 `--fs-sm`, `--fw-semibold`, `--text-2`로 올려 kv 라벨보다 강하게 만듭니다.

## 4. 세 방향의 대비

세 안이 서로 충분히 다르다고 보기는 어렵습니다. mixed와 ops는 뼈대가 같습니다. 채팅은 탐색 막대 · 대화 목록 · 대화 열의 3단, 결재는 표 + 오른쪽 상세, 미리보기 카드 구성까지 같고 차이는 밀도(행 40 / 32px), 모서리(8 / 2px), 탐색 막대 색(연회색 / 흑연), 강조색(코발트 / 청록) 같은 겉모습뿐입니다. 그래서 사용자 눈에는 "같은 화면의 밝은 판과 어두운 판"으로 보이고, 셋 중 가운데인 mixed를 고르기 쉬운 구도가 됩니다. 실제로 구조가 다른 안은 assistant 하나입니다(대화 목록 없음, 확인할 일 오른쪽 패널, 카드 목록). 하지만 assistant는 결재 목록을 카드로 바꾸면서 업무 도구 기준을 스스로 잃어서, 구조 대안으로서 공정한 비교 상대가 되지 못합니다. 고르기 좋은 대비를 만들려면 축을 둘로 나누는 편이 낫습니다. 구조 축은 "대화 목록형(mixed)" 대 "확인 패널형(assistant, 단 결재는 표로)"으로, 밀도·인상 축은 ops의 표 밀도와 흑연 셸을 어느 구조에도 얹을 수 있는 선택지로 따로 보여 줍니다. 지금 셋을 나란히 두면 사용자는 구조와 겉모습을 한꺼번에 고르게 됩니다.
