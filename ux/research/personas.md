# 페르소나와 핵심 과업

이 문서의 페르소나는 실제 사용자 인터뷰에서 나온 것이 아닙니다. 기획서의 가상 회사(중견 제조사, 약 60명)와 1~3단계 범위, 웹 화면의 실제 기능을 바탕으로 지어낸 **가상 사용자**입니다. 사용성 결과도 모두 이 가상 사용자를 둔 에이전트·스크립트의 결과입니다.

각 페르소나는 웹 모의 데이터 모드(`web/src/mocks/data.ts`)의 계정 하나로 로그인합니다. 모의 계정의 이름·부서는 페르소나와 다를 수 있습니다. 과업을 돌리는 데 필요한 권한(결재자, 감사 조회)만 맞췄습니다.

## 1. 페르소나

| | 직원 | 결재자 | 관리자 |
|---|---|---|---|
| 역할 | 생산관리팀 팀원 3년차 | 생산관리팀 팀장 14년차 | IT운영팀 담당(감사 조회 권한) 6년차 |
| 쓰는 일 | 휴가·경비 결재 올리기, 회의실, 규정 묻기 | 팀원 결재 승인·반려, 출장 때 대결 맡기기 | 외부 모델 전송·비용 점검, 감사 기록 조회, 평가 리포트 확인 |
| 업무 도구 숙련도 | 중간. 그룹웨어 결재는 익숙하지만 AI 채팅은 처음 | 낮음~중간. 새 도구를 배울 시간이 없고, 결재 화면은 "내 차례"만 봄 | 높음. 표·필터·키보드 위주 |

| 바라는 것 | 말로 시키고 확인만 하기 | 한 화면에서 판단할 정보가 다 보이기 | 기간·에이전트로 거르고 사람 이름으로 읽기 |
| 모의 계정 | E1001 | E2001 | E2008 |

## 2. 과업과 성공 기준

과업은 로그인 뒤 첫 화면(채팅)에서 시작합니다. 기준은 두 종류입니다.

- **완료:** 과업의 끝 상태에 닿았는지. 하나라도 못 채우면 "실패"입니다.
- **확인:** 사람이 판단에 필요한 정보를 화면에서 읽을 수 있었는지. 완료는 했지만 확인 기준을 못 채우면 "부분 성공"입니다.

스크립트는 `ux/walkthrough/tasks.mjs`입니다. 재설계 뒤(#564)에도 같은 과업·기준으로 다시 돌립니다.

### 직원

| 번호 | 과업 | 완료 기준 | 확인 기준 |
|---|---|---|---|
| E1 | 영수증 사진으로 경비 정산 올리기 | 경비 정산 실행 | 금액이 `42,000원` 형식 / 값 이름이 한국어(가맹점·사용일·금액) / 결재선이 보임 / 사진에서 읽은 값이라 확인이 필요하다는 표시 |
| E2 | 회의실을 예약했다가 되돌리기 | 예약을 되돌림 | 예약한 회의실·시각이 결과에 보임 / 되돌린 뒤 표시가 바뀜 |
| E3 | 연차 규정을 묻고 근거 조문 확인하기 | 답과 근거 조문을 읽음 | 펼치지 않아도 근거가 있다는 것이 보임 / 확인 안 된 인용이 구별됨 |
| E4 | 내가 올린 휴가 결재가 어디까지 갔는지 보기 | 올린 문서를 엶 | 지금 누구 차례인지 보임 / 기간·종류가 한국어 이름으로 보임 |
| E5 | 잘못 올린 반차 결재를 회수하기 | 회수 실행 | 되돌릴 수 없다는 경고가 실행 전에 보임 / 무엇이 어떻게 바뀌는지 한국어로 보임 |

### 결재자

| 번호 | 과업 | 완료 기준 | 확인 기준 |
|---|---|---|---|
| A1 | 내 차례인 휴가 결재 승인하기 | 승인 | 승인 전에 기간·종류·사유가 보임 / 승인한 문서가 처리함에 있음 |
| A2 | 대결로 들어온 경비 정산 승인하기 | 대결 문서 승인 | 원 결재자(누구 대신인지)가 보임 / 금액이 `320,000원` 형식 / 다음 결재자가 보임 |
| A3 | 출장 동안 휴가 결재만 팀원에게 맡기기 | 위임 등록 | 등록 전 미리보기에 대리인·기간·범위가 한국어로 보임 / 등록한 위임이 목록에 보임 |

### 관리자

| 번호 | 과업 | 완료 기준 | 확인 기준 |
|---|---|---|---|
| M1 | 외부 모델로 나간 요청에서 개인정보가 가려졌는지 보기 | 기록 한 건의 본문을 엶 | 가린 자리가 본문에서 구별됨 / 어느 직원·어느 대화의 요청인지 보임 |
| M2 | 지난 7일 에이전트별 외부 비용과 차단 수 보기 | 지난 7일 에이전트별 표를 봄 | 비용 단위(통화)가 분명함 / 지금 보는 기간이 표 근처에 보임 |
| M3 | 감사 로그에서 차단된 도구 실행 찾기 | 도구 차단 이벤트를 걸러 봄 | 직원이 이름으로 보임 / 에이전트·작업이 사람이 읽는 이름으로 보임 |
| M4 | 평가 리포트에서 기대와 다른 시나리오 하나 열어 보기 | 회차 상세를 엶 | 시나리오가 사람이 읽는 제목으로 보임 / 기대와 다른 이유가 한 줄로 보임 |

## 3. 과업을 고른 이유

- 직원 과업은 기획서 단계별 범위의 쓰기(경비·휴가·회의실)와 질의(규정)를 하나씩 덮고, 쓰기 안전 장치(미리보기, 되돌리기, 되돌릴 수 없음 경고)를 사람이 실제로 읽는지 봅니다.
- 결재자 과업은 결재 대결(기획서 "정해진 것" 9)을 사람 쪽에서 봅니다. 대결은 "누구 대신, 어느 범위로"가 화면에서 분명해야 사고가 나지 않습니다.
- 관리자 과업은 평가자가 물을 질문("외부 모델로 무엇이 나가는지")에 화면으로 답할 수 있는지 봅니다.
- 이번 기준선은 데스크톱 폭(1280~1920)만 돌립니다. 지금 화면의 좁은 폭 배치는 일부 화면(채팅·승인함·조직도·관리)에 한 구간씩만 있고, 태블릿·노트북 배치는 #557 범위입니다. 재설계 뒤 같은 과업을 태블릿 폭으로도 돌립니다.
