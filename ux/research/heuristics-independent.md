# 닐슨 10원칙 휴리스틱 평가 (독립 평가)

평가자는 사람이 아니라 결론을 모르는 서브에이전트입니다([heuristics.md](heuristics.md)의 평가 2). 다른 평가 결과를 보지 않고 혼자 했습니다. `ux/research/` 아래 문서는 `personas.md`만 읽었습니다. 브라우저나 서버는 띄우지 않았고, 이미 찍어 둔 화면과 `web/src/` 코드만 봤습니다.

## 근거 표기

- **[모의]** 모의 데이터 모드 화면: `ux/research/a11y/baseline/shots/`, `ux/research/walkthrough/baseline/shots/`
- **[실제]** 실제 스택(실제 모델·erp)으로 찍은 화면: `web/docs/images/real-*.png`
- **[코드]** 화면에서 확인하기 어려운 동작(확인 단계 여부, 비활성 조건 등)을 `web/src/`에서 확인한 것입니다. 화면에 같은 현상이 보일 때만 문제로 셌습니다.
- 원칙은 문제마다 가장 가까운 하나만 적었습니다. 집계도 이 원칙 하나로 했습니다.
- 심각도: **사용을 막음** / **헷갈림** / **다듬기**

원칙: N1 시스템 상태 보이기, N2 실제 세계와 맞는 말, N3 사용자 통제와 자유, N4 일관성과 표준, N5 오류 예방, N6 기억보다 알아보기, N7 유연성과 효율, N8 미적·최소 디자인, N9 오류 알아보기·진단·복구, N10 도움말과 문서

## 시각 디자인 총평("현대적인 업무 도구" 방향과 견줌)

1. 회색 바탕, 흰 카드, 얇은 테두리, 알약 배지로 깔끔하지만, 어느 화면도 강조점이 없어 2020년 전후 관리자 템플릿처럼 보입니다. 브랜드 색·타이포 위계·밀도에서 "트렌디함"은 거의 느껴지지 않습니다.
2. 정보 위계가 평평합니다. 금액·결재선·위험 같은 판단 정보와 ID·버전·코드명 같은 부가 정보가 같은 크기와 색으로 나와 눈이 갈 곳이 없습니다(미리보기 카드, 에이전트, 평가 실행 조건).
3. 배지가 상태·위험·라우팅·처리 위치를 모두 같은 알약 모양으로 나타내 의미 구분을 색 하나에만 기대고, 주황이 "안전함"과 "주의"를 같이 맡습니다.
4. 레이아웃이 화면마다 따로 놉니다(머리글 띠, 본문 폭, 고정 오른쪽 패널). 넓은 화면에서는 표가 늘어나 빈 공간이 크고, 좁은 화면 대응은 일부 화면에만 있습니다.
5. 어두운 테마는 색을 뒤집는 데 그쳐 주요·위험 버튼의 대비와 위계가 약해집니다. 현대적 업무 도구 수준이 되려면 표시 이름 정리와 함께 카드·배지·버튼의 위계 규칙부터 다시 세우는 것이 먼저로 보입니다.
