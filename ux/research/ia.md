# 정보 구조와 핵심 흐름

재설계(#558)의 1단계 산출물입니다. 사용자 확인 ①에서 이 구조를 봅니다. 화면 모양(색·밀도·서체)은 정하지 않고, **무엇이 어디에 있고 어떤 순서로 가는지**만 정합니다. 모양은 #563(디자인 시스템)에서 정합니다.

근거는 [baseline.md](baseline.md)의 과업 걸어 보기, [heuristics.md](heuristics.md)(두 평가와 합친 우선순위), 기획서의 사용자 유형과 범위입니다. 기능·API는 바꾸지 않습니다. 지금 있는 화면과 API로 만들 수 있는 구조만 넣었습니다.

## 1. 지금 구조

```
머리글: 사내 AI 비서 | 채팅 · 승인함 · 조직도 · 에이전트 · (관리 · 평가) | 이름 부서 | 로그아웃
  /          채팅          대화 목록 | 대화 + 에이전트 선택 + 입력
  /inbox     승인함        탭(내 차례·대결·처리함·올린 것) + 목록 아래 상세 | 오른쪽 대결 설정 패널
  /org       조직도        부서 트리 | 부서 상세(구성원·하위 부서·담당 에이전트)
  /agents    에이전트      에이전트 카드 나열
  /admin     관리(감사)    기간 필터 + 탭(운영 지표·외부 전송 기록·감사 로그)
  /eval      평가(감사)    보고서 하나의 긴 페이지
  /login     로그인
```

문제(휴리스틱 번호):

- 모든 사용자가 채팅으로 들어옵니다. 결재자·관리자의 할 일이 첫 화면에 없습니다(H-S2).
- 탐색이 글자 링크 한 줄이고 결재 건수 같은 상태가 없습니다(H-S1).
- 승인함 한 화면에 결재 처리와 대결 설정이 같은 무게로 섞여 있습니다(H-I2).
- 관리 콘솔은 탭 세 개가 한 주소를 써서, 감사 로그를 바로 여는 링크를 만들 수 없습니다.

## 2. 제안 구조

왼쪽 탐색 막대(아이콘 + 이름, 접기)와 명령 팔레트(Ctrl+K)를 둡니다. 메뉴를 **업무 / 회사 / 운영** 세 묶음으로 나누고, 운영은 감사 권한이 있을 때만 보입니다.

```
[왼쪽 탐색 막대]
  업무
    AI 비서            /                  대화 목록 + 대화
    결재               /approvals         받은 결재(n) · 대결로 받은 결재(n) · 처리한 결재 · 올린 결재
    대결 설정          /delegations       내가 맡긴 위임 · 내가 맡은 위임 · 새 위임
  회사
    조직도             /org               부서 트리 + 사람 찾기
    AI 에이전트        /agents            에이전트별 할 수 있는 일·정책
  운영(감사 권한)
    운영 지표          /ops/metrics
    외부 전송 기록      /ops/egress
    감사 로그          /ops/audit
    평가 보고서        /ops/eval
  ─────
  [이름 · 부서]  → 메뉴: 테마(밝음·어두움·시스템), 로그아웃
[머리글]  현재 위치(제목) · 화면별 주 동작 · Ctrl+K · 알림(erp 알림·대결 후열, 지금 계약의 /notifications)
```

| 바꾸는 것 | 이유 | 근거 |
|---|---|---|
| 승인함 → **결재**, 탭 이름을 "받은 결재 / 대결로 받은 결재 / 처리한 결재 / 올린 결재"로 | "처리함", "올린 것"의 기준이 이름으로 드러나지 않음. 탭에 건수 표시 | H-I6, 페르소나 결재자 |
| 대결 설정을 결재에서 떼어 **별도 메뉴** | 매일 쓰는 결재 목록의 3분의 1을 가끔 쓰는 기능이 차지함 | H-I2 |
| 대결 목록을 "내가 맡긴 / 내가 맡은"으로 나눔 | "윤서진 → 서도윤" 화살표만으로 방향을 읽어야 함 | H-D3 |
| 관리 탭 셋을 **운영 묶음의 메뉴 넷**(평가 포함)으로 | 화면마다 주소가 생겨 감사 로그·외부 전송 기록으로 바로 갈 수 있음. 기간 필터는 운영 화면끼리 공유 | H-A3 |
| 에이전트 → **AI 에이전트**, 회사 묶음 | 직원이 "무엇을 시킬 수 있는지" 찾는 안내 화면. 조직도와 같은 참고 성격 | H-O2, H-C6 |
| 조직도에 **사람 찾기** | 트리를 내려가야만 사람을 찾을 수 있음 | H-O1 |

### 첫 화면(사용자 확인 ① 결정 지점)

| 안 | 내용 | 좋은 점 | 아쉬운 점 |
|---|---|---|---|
| **A. 역할별 첫 화면(추천)** | 직원은 AI 비서, 받은 결재가 있는 결재자는 결재, 감사 권한자는 운영 지표로 들어감. 새 화면 없음 | 새 기능 없이 H-S2를 고침. 지금 API로 됨(`/inbox` 건수) | 같은 사람이 날마다 다른 화면으로 들어갈 수 있음 |
| B. 홈 화면 새로 둠 | "내 할 일"(받은 결재 n건, 진행 중인 내 결재, 최근 대화, 자주 하는 일 바로가기) | 모든 역할이 같은 곳에서 시작. 트렌디한 SaaS 첫 화면 | 새 화면 하나를 더 만들고 유지해야 함. 이번 범위(#558)보다 넓어짐 |

### 명령 팔레트(Ctrl+K)에 넣을 동작

새 대화 · 받은 결재 열기 · 결재 문서 찾기(제목) · 새 위임 · 사람 찾기 · 화면 이동(메뉴 전부) · 테마 바꾸기. 모두 지금 화면에 있는 동작이고 새 API가 필요 없습니다.

## 4. 핵심 흐름 다섯

와이어프레임: [wireframes/index.html](wireframes/index.html)(브라우저로 엶), 그림: `wireframes/*.png`

### F1. 직원: 영수증으로 경비 정산(E1)

```
AI 비서 → [사진 첨부] → 메시지 → 재무 에이전트 답
  → 미리보기 카드: 가맹점 · 사용일 · 금액 42,000원 · 용도 · 사업자번호 / 결재선 1 서도윤 팀장
     "사진에서 읽은 값입니다. 영수증과 맞는지 확인하세요" + 영수증 썸네일 나란히
  → [경비 정산 올리기] → 실행한 일: "결재 EXP-0107을 올렸습니다" [결재 문서 보기] [되돌리기]
```

바뀌는 점: API 원문 대신 양식 표시 이름 순서로 보여 주고(#556), 영수증과 값을 나란히 둬 대조하게 합니다. 실행 버튼은 동사 + 대상("경비 정산 올리기")으로 씁니다(H-P5).

### F2. 직원: 올린 결재 확인과 회수(E4, E5)

```
결재 → 올린 결재 → 문서 선택 → 오른쪽 상세: 결재선 진행 표시(1 서도윤 · 결재 차례)
  → [AI 비서로 회수] → AI 비서 새 대화에 "APR-0042 결재 회수해 줘"가 채워짐
  → 미리보기 카드: 휴가 결재 APR-0042 · 11/24 오후 반차 · 상태 결재 중 → 회수됨
     "회수하면 되돌릴 수 없습니다. 다시 올려야 합니다" → [결재 회수하기]
```

바뀌는 점: `status pending → withdrawn` 대신 상태 이름(H-P2). gateway 계약에는 웹용 회수 경로가 없고(`/inbox/{id}/approve`·`reject`뿐) 회수는 에이전트 도구(`approval_withdraw`)입니다. 그래서 결재 화면에서는 AI 비서로 넘기는 버튼만 두고, 확인은 채팅의 미리보기 카드 한 곳에서 받습니다.

### F3. 결재자: 받은 결재 승인(A1, A2)

```
(로그인 → 결재로 바로, 안 A) 받은 결재(2) · 대결로 받은 결재(1)
  → 목록에서 행 선택 → 오른쪽 상세
     머리: 제목 · 상태 · [대결: 윤서진 대신, 11/24까지]
     본문: 요청자 · 금액 320,000원 · 양식 값(표시 이름 순서)
     결재선: ● 1 윤서진(대신 처리 중) → ○ 2 임채원
     의견 입력
  → [승인] → 목록에서 사라지고 다음 문서가 열림 / [반려]는 의견을 받아야 누를 수 있음
```

바뀌는 점: 목록-상세 나란히(H-I3), 승인 뒤 다음 문서(N7), 반려 의견 필수(H-I4).

### F4. 결재자: 출장 전 대결 설정(A3)

```
대결 설정 → [새 위임] → 오른쪽 서랍
  1 대리인: 이름 찾기 → 선택
  2 기간: 2026. 11. 23. 09:00 ~ 2026. 11. 25. 18:00 (한국식 날짜 고르개)
  3 범위: ○ 모든 양식  ● 고른 양식 [휴가 신청 ✓] [경비 정산] [구매 요청] · 금액 한도
  4 사유
  → 미리보기: "한지우님이 11/23 09:00~11/25 18:00 동안 휴가 신청 결재를 대신합니다"
  → [위임 등록] → 내가 맡긴 위임 목록에 추가
```

바뀌는 점: 범위를 라디오(모든 양식 / 고른 양식)로 바꿔 체크박스 비활성 함정을 없애고 기본값을 좁은 쪽(고른 양식)으로 둠(H-D4, 평가 2 D4), 미리보기를 한 문장으로(H-D1), 한국식 날짜(H-D2). 대리인이 내 차례 문서의 요청자 본인이면 "이 문서는 위임 기간에 처리할 사람이 없습니다"를 미리보기에 띄움(페르소나 관찰). 해지에는 확인을 받음(평가 2 D7).

### F5. 관리자: 외부 전송·비용 점검(M1, M2, M3)

```
운영 지표(기간: 최근 7일) → 에이전트별 표의 "외부 비용" 칸 → 전사 비서 행 선택
  → 외부 전송 기록(전사 비서, 같은 기간으로 걸러짐)
     행: 시각 · 에이전트 · 직원 이름 · 모델 · 가림 2곳(전화번호, 이메일) · 토큰 · 비용
  → 행 펼침: 보낸 본문(가린 자리 강조) · [이 대화의 감사 로그 보기]
  → 감사 로그(같은 대화로 걸러짐)
```

바뀌는 점: 운영 화면끼리 기간·에이전트 거르기를 들고 이동(H-A3), 이름으로 표시(H-A1).

## 5. 확인 ①에서 사용자에게 묻는 것

1. 첫 화면: 안 A(역할별, 추천) / 안 B(홈 새로 둠)
2. 메뉴 묶음과 이름: 업무(AI 비서·결재·대결 설정) / 회사(조직도·AI 에이전트) / 운영(운영 지표·외부 전송 기록·감사 로그·평가 보고서)
3. 대결 설정을 결재에서 떼어 별도 메뉴로 두는 것
4. 결재 목록-상세 나란히 배치
