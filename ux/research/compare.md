### 2.2 읽는 법

- **직원 과업은 모두 성공이 됐습니다.** 실행 전 확인 카드가 금액을 `42,000원`으로, 값 이름을 한국어로, 회수 카드가 상태를 한국어로 보여 줍니다(재설계 전 우선순위 1·3).
- **역할별 첫 화면이 움직임을 줄였습니다.** 결재자는 로그인하면 바로 결재 화면, 관리자는 운영 지표 화면에 섭니다. A1·A2·M2에서 "메뉴로 이동"이 필요 없어졌습니다(스크립트는 이 단계를 "이미 그 화면"으로 남기고 세지 않음). A1·A2의 클릭 수가 그대로인 것은 그만큼 승인 확인 팝오버가 한 번 늘었기 때문입니다(누르는 횟수는 같고, 되돌릴 수 없는 승인을 한 번 더 확인함).
- **A3(대결 지정)는 클릭이 6 → 14로 늘었습니다.** 시작·끝을 글자로 입력하던 것(16자 × 2)이 날짜 고르개(달력 열기 → 날 고르기 → 시 고르기, 두 번)로 바뀌었기 때문입니다. 입력 글자는 37자 → 5자로 줄었고 미국식 날짜 문제는 사라졌지만, 기준선의 목표(조작 단계 10 → 7 이하)와 반대로 갔습니다. 빠른 기간 단추("내일부터 3일" 등)나 날짜 직접 입력을 함께 두면 줄일 수 있습니다.
- **관리자 과업 넷은 여전히 부분 성공입니다.** 남은 넷 중 셋(M1 직원·대화, M2 기간 위치, M4 시나리오 제목)은 화면 배치나 계약 값의 문제로 재설계 범위 밖이었고, M3는 2.3의 해석 문제입니다.
- **태블릿(768×1024):** E1·A1·A2·A3을 태블릿 폭으로 돌려 데스크톱과 같은 결과를 얻었습니다(E1·A1·A2 성공, A3 부분 성공). 탐색 막대는 아이콘으로 접히고 결재 상세는 목록 아래로 쌓입니다([after-tablet/](walkthrough/after-tablet/)).

### 2.3 M3 판정에 대해

M3의 기준 "직원이 이름으로 보인다", "에이전트·작업이 사람이 읽는 이름으로 보인다"는 스크립트가 "코드(`emp-…`, `hr`, `delegation_register`)가 없다"로 판정합니다. 재설계 뒤 감사 로그는 `윤서진 emp-2002`, `인사 hr`, `대결 지정 delegation_register`처럼 이름 뒤에 코드를 작게 붙입니다. 이것은 copy-guide 1.4("직원: 이름(사번)", "표시 이름, 코드 이름은 작게 뒤에")가 허용한 모양이라 **기준의 뜻은 채웠다고 봅니다.** 스크립트 판정은 고치지 않고 부분 성공 그대로 두었습니다(전후를 같은 판정으로 견주기 위해).

## 3. 휴리스틱 평가

### 3.1 독립 평가끼리

같은 방식(결론을 모르는 서브에이전트, 같은 심각도 정의, 원칙 하나씩)으로 전후를 따로 평가했습니다. 평가자가 다른 인스턴스라 몇 건의 차이는 잡음일 수 있습니다.

| 심각도 | 전 | 뒤 |
|---|---|---|
| 사용을 막음 | 3 | 1 |
| 헷갈림 | 41 | 15 |
| 다듬기 | 40 | 40 |
| **합계** | **84** | **56** |

- 사라진 "사용을 막음"은 실행 미리보기의 날것 값(모의·실제 둘)과 확인 없는 승인·반려입니다.
- **남은 "사용을 막음" 1건(G-1):** 새 대결 지정의 기본값이 "모든 양식 + 금액 한도 없음"이고, 이때 개별 양식 체크 상자가 비활성이며, 확인 카드에 "범위가 넓은 대결" 경고가 없습니다. 재설계 전에도 있던 문제(평가 1 H-D4, 독립 평가 D4)인데, 다른 문제가 줄면서 가장 위험한 문제가 됐습니다. 명세(ia.md F4, design-system 3.5)는 "고른 양식"을 기본으로 하고 라디오로 바꾸라고 했지만 구현되지 않았습니다.
- 헷갈림이 41 → 15로 줄어든 것이 가장 큰 변화입니다. 다듬기 40건은 그대로이고, 상당수는 명세·용어집과 어긋나는 세부(3.3)입니다.

### 3.2 재설계 전 문제의 해결 여부

평가 1(이 세션)의 40건과 페르소나 관찰에서만 나온 항목을 하나씩 대조했습니다([resolution.md](resolution.md)).

| 재설계 전 심각도 | 해결 | 일부 | 남음 |
|---|---|---|---|
| 사용을 막음(1) | 1 | 0 | 0 |
| 헷갈림(29) | 12 | 7 | 10 |
| 다듬기(18) | 10 | 2 | 6 |
| **합계(48, 겹침 2건 포함)** | **23** | **9** | **16** |

남은 것 중 우선:

- 대결: 맡긴/맡은 대결이 화살표로만 구별(H-D3), "모든 양식"을 꺼야 열리는 체크 상자(H-D4), 대결자가 내 차례 문서의 기안자 본인일 때 경고 없음(P-1), 확인 카드의 `양식 leave`(H-D1 일부)
- 관리: 외부 전송 기록에 직원·대화 없음(H-A3, 계약 필요), 감사 로그 종류 칸의 출처 코드(H-A2), 비용이 달러뿐(H-A5)
- 평가 보고서: 시나리오 ID(H-E1), 긴 페이지·메타 먼저(H-E2·E3)
- 채팅: 실행 취소한 뒤에도 답 문장이 "예약했습니다"로 남음(B-3), 확인 시간이 시각만(H-P4)

## 4. 접근성(axe-core)

| 화면 | 전 | 뒤 |
|---|---|---|
| 로그인, 로그인 오류 | 0 | 0 |
| 채팅 세 상태 | `landmark-one-main`, `page-has-heading-one`(각 2요소) | `label-content-name-mismatch`(각 2요소) |
| 결재 대기, 결재 상세, 대결 지정 확인 | 0 | `label-content-name-mismatch`(3~4요소) |
| 조직도, 평가 보고서 | 0 | `label-content-name-mismatch`(2요소) |
| AI 에이전트 | 0 | `label-content-name-mismatch`(2), `landmark-unique`(1) |
| 운영 지표, 외부 전송 기록, 감사 로그 | 0 | `label-content-name-mismatch`(4요소) |
| **합계(밝음·어두움 28회)** | **12요소, moderate** | **72요소, serious 70 · moderate 2** |

- **고친 것:** 채팅 화면에 `main`과 `h1`이 생겨 재설계 전 유일한 위반이 사라졌습니다.
- **새로 생긴 것: `label-content-name-mismatch`(WCAG 2.5.3 Label in Name, serious).** 보이는 글자가 접근 가능한 이름 안에 없는 요소입니다. 음성 입력으로 "찾기·이동 누르기"처럼 보이는 글자를 말해 조작하는 사람이 누를 수 없습니다. 걸린 곳은 넷입니다.
  - 탐색 막대 찾기 단추: 보이는 글자 "찾기·이동 Ctrl K", 이름 "찾기·이동"(`web/src/shell/Sidebar.tsx:37`)
  - 사용자 메뉴 단추: 보이는 글자 "서도윤 인사팀 팀장", 이름 "서도윤 사용자 메뉴"(`Sidebar.tsx:74`)
  - 결재 목록 행 단추: 보이는 글자에 양식·기안자·시각이 더 있는데 이름은 제목만(`#doc-open-*`)
  - 운영 화면 기간의 날짜 단추: `aria-labelledby` 조합이 보이는 글자와 다름
  - axe는 이 규칙을 "실험적"으로 표시합니다. 재설계 전에도 같은 규칙 묶음으로 돌렸고 0건이었으므로 회귀로 봅니다.
- `landmark-unique`(moderate): AI 에이전트 화면에서 이름이 같은 구역이 둘.
- **axe가 판정하지 못한 색 대비:** 152 → 270요소. 반투명 면과 흐림(사이드바, 팝오버)이 늘어 자동 계산이 안 되는 요소가 늘었습니다. 토큰 수준의 대비는 `ux/design-system/tokens.test.mjs`가 반투명 면을 섞어 계산해 확인합니다(23쌍, 밝음·어두움 통과).
