# 화면 문구 기준: 용어집과 문체 원칙

사용자가 보는 문구(화면, 슬랙, 에이전트의 고정 안내, 오류 문구, 팩의 표시 이름)를 쓸 때 따르는 기준입니다. 한국 회사 그룹웨어·전자결재에서 실제로 쓰는 말과 일반 소프트웨어 관례를 기준으로 삼고, AI 말투와 영어 직역투를 피합니다.

- 적용 범위: `web/`, `channels/slack/`, `agent/`의 고정 문구, `gateway/`·`erp/`가 사용자에게 돌려주는 오류 문구, `packs/`의 표시 이름
- 지금 문구의 점검 결과: [copy-audit.md](copy-audit.md)
- 이 문서는 기준만 정합니다. 코드 반영은 모듈별 후속 이슈에서 합니다(#572).

## 1. 용어집

"지금"은 지금 화면에 나오는 말, "바꿀 말"은 앞으로 쓸 말입니다. 같은 개념은 화면·슬랙·에이전트 답·오류 문구에서 같은 말로 씁니다.

### 1.1 전자결재

| 개념 | 지금 | 바꿀 말 | 이유 |
|---|---|---|---|
| 결재 문서를 써서 올림 | 결재 요청, 결재 올리기, 상신 | **기안**(문서를 씀), **상신**(결재선에 올림). 버튼은 "상신", 안내는 "결재를 올렸습니다"도 허용 | 그룹웨어 표준어. 직원에게 "기안"·"상신"은 익숙한 말입니다 |
| 결재할 차례가 온 문서 함 | 승인함, 내 차례, 받은 결재 | **결재 대기** | 그룹웨어의 "결재대기함". "승인함"은 승인만 하는 곳처럼 들립니다 |
| 대결로 맡은 문서 함 | 대결, 대결로 받은 결재 | **대결 대기** | 결재 대기와 짝을 맞춤 |
| 내가 처리한 문서 함 | 처리함, 처리한 결재 | **결재 완료** | "처리함"은 동사로도 읽힙니다 |
| 내가 올린 문서 함 | 올린 것, 올린 결재 | **기안함** | 그룹웨어 표준. "올린 것"은 구어 |
| 결재 화면(메뉴) | 승인함 | **결재** | 기안·결재·대결을 모두 담는 이름 |
| 승인 | 승인 | **승인** | 유지 |
| 되돌려 보냄 | 반려 | **반려** | 유지. 반려에는 사유를 받습니다 |
| 기안자가 결재 전에 거둬들임 | 회수 | **회수** | 유지 |
| 부재 중 다른 사람이 대신 결재 | 대결, 위임, 대리 결재 | **대결**. 맡는 사람은 **대결자**, 맡기는 일은 **대결 지정** | "위임"은 권한 위임 전반을 뜻해 넓습니다. 화면에서는 "대결"로 통일하고 "위임"은 쓰지 않습니다 |
| 대결을 맡는 사람 | 대리인 | **대결자** | 그룹웨어 표준 |
| 대결 지정을 끝냄 | 해지 | **대결 해제** | "해지"는 계약 용어 |
| 대결 뒤 원 결재자가 확인 | 후열 | **후열** | 유지. 처음 보는 사람을 위해 "후열(대결 내역 확인)"처럼 한 번 풀어 씁니다 |
| 결재 순서와 사람 | 결재선 | **결재선** | 유지 |
| 결재 순서에서 지금 차례 | 결재 차례 | **결재 대기** | 문서 상태와 같은 말 |
| 결재선에서 아직 안 온 차례 | 대기 | **예정** | "대기"가 지금 차례와 겹침 |
| 진행 중인 문서 상태 | 진행, in_progress | **진행 중** | |
| 의견 | 의견(선택, 200자) | **의견**, 반려일 때 **반려 사유** | 글자 수 제한은 칸 아래 작게 |
| 결재 양식 | 양식 | **양식** | 유지. 양식 이름은 팩의 표시 이름 그대로 |
| 연차·반차 | 연차, 오후 반차, annual, half_pm | **연차**, **오전 반차**, **오후 반차** | 코드 값은 화면에 내지 않습니다 |

### 1.2 AI 비서와 실행

| 개념 | 지금 | 바꿀 말 | 이유 |
|---|---|---|---|
| 실행한 일을 원래대로 | 되돌리기, 되돌림 | 버튼 **실행 취소**, 결과 **취소됨** | "되돌리기"는 undo 직역. 소프트웨어 관례는 "실행 취소" |
| 실행 취소가 되는 일인지 | 되돌릴 수 있음 / 되돌릴 수 없음 | **실행 취소 가능** / **실행 취소 불가** | 버튼 이름과 같은 말로 묶음 |
| 실행 전에 보여 주는 카드 | 실행 미리보기 | **실행 전 확인** | 사람이 할 일(확인)을 이름에 둠 |
| 카드의 실행 버튼 | 실행 | 일 이름 동사: **경비 정산 상신**, **회의실 예약**, **결재 회수** | 무엇이 일어나는지 버튼에 보임 |
| 실행 결과 표시 | 실행됨, 실행함 | **완료** | 두 말이 섞여 있음 |
| 확인 카드의 남은 시간 | 만료 21:22 | **21:22까지 확인** / 지나면 **확인 시간 지남** | "만료"는 무엇이 끝나는지 모호 |
| 사내 모델로 처리했다는 표시 | 로컬에서 처리 | **사내 처리** | "로컬"은 개발 용어. 직원에게 중요한 것은 "회사 밖으로 안 나감" |
| 외부 AI 모델을 씀 | 외부 모델, external | 직원 화면 **외부 AI 사용**, 관리 화면 **외부 모델** | 관리자는 모델 개념을 압니다 |
| 부서별 AI | 부서 에이전트, 에이전트 | **AI 에이전트**(목록·설정), 대화 안에서는 **재무 담당 AI**처럼 부서 이름 | |
| 에이전트를 고르는 방식 | 자동 선택, LLM이 골랐습니다, 낱말 | **자동 선택**. 고른 이유는 펼쳐서 한 줄로 | 방식 이름(LLM, 낱말)은 관리 화면에만 |
| 답의 근거 | 근거 n건 | **근거 규정 n건** | |
| 인용이 원문과 맞는지 확인 못 함 | 인용 확인 안 됨 | **원문 대조 안 됨** | 무엇을 확인 못 했는지 드러냄 |
| 에이전트가 부른 기능 | 도구 실행 policy_search | 직원 화면에서는 숨김. 펼치면 **규정 검색** 같은 표시 이름 | 코드 이름은 화면에 내지 않습니다 |
| 정책으로 막힘 | 차단, blocked | 직원 화면 **처리할 수 없는 요청**, 관리 화면 **정책 차단** | 직원에게는 이유와 다음 행동을 알림 |
| 사진에서 읽은 값 | 이미지에서 읽은 값(확인 필요) | **사진에서 읽은 값** 배지 + "영수증과 맞는지 확인해 주세요" | 화면 전체에서 "사진"으로 통일 |

## 2. 문체 원칙

### 2.1 말 높이

- 안내·결과·오류 문장은 **합니다체**로 씁니다("상신했습니다", "권한이 없습니다"). 해라체를 섞지 않습니다.
- 사용자에게 할 일을 알릴 때는 "~하세요" 또는 "~해 주세요"를 씁니다. "~하십시오", "~해 주시기 바랍니다", "~하시면 됩니다"는 쓰지 않습니다.
- 예외는 사용자가 쓰는 입력 예시(`예: 다음 주 화요일 회의실 잡아 줘`)뿐입니다.

### 2.2 버튼과 메뉴

- 버튼은 **동사 명사형, 2~6자**: `상신`, `승인`, `반려`, `저장`, `실행 취소`, `다시 시도`. "~하기"를 붙이지 않습니다(`저장하기` → `저장`).
- 무엇이 일어나는지 버튼에 드러냅니다. 같은 카드에 버튼이 둘이면 둘 다 동작 이름입니다(`취소` / `경비 정산 상신`).
- 위험한 동작은 동작 이름 그대로 쓰고 색과 확인 단계로 구별합니다(`결재 회수`, `대결 해제`). "삭제하시겠습니까?"처럼 묻는 버튼은 쓰지 않습니다.
- 메뉴·탭은 명사: `결재`, `결재 대기`, `대결 설정`.

### 2.3 안내 문장

- **한 문장, 결과 먼저.** "경비 정산을 상신했습니다." 다음 행동이 있으면 한 문장 더: "필요 없으면 실행 취소를 누르세요."
- 오류는 **무슨 일이 났는지 + 할 일**: "회의실 C는 그 시간에 이미 예약돼 있습니다. 다른 시간을 고르세요." 사과("죄송합니다")와 모호한 말("오류가 발생했습니다")만으로 끝내지 않습니다.
- 빈 상태는 상태 + 다음 행동: "결재할 문서가 없습니다."(다음 행동이 없으면 한 문장으로 끝).
- 숫자는 단위를 붙입니다: `42,000원`, `3건`, `9분 남음`. 날짜는 목록 `오늘 12:44`·`어제`·`11월 20일`, 상세 `2026년 11월 21일 12:44`.

### 2.4 피할 것

| 분류 | 예(나쁨 → 좋음) |
|---|---|
| **직역투: 무생물 주어·피동** | "요청이 처리되었습니다" → "요청을 처리했습니다", "~되어집니다"(이중 피동) → "~됩니다" |
| **직역투: ~를 가지다, ~에 대해, ~를 통해** | "권한을 가지고 있지 않습니다" → "권한이 없습니다", "결재에 대해 확인" → "결재 확인", "슬랙을 통해 알림" → "슬랙으로 알림" |
| **직역투: 영어 단어 그대로** | "되돌리기(undo)", "미리보기(preview)", "로컬", "에러", "리스트" → 1절의 말 |
| **AI 말투: 과한 공손** | "~해 드리겠습니다", "~해 드릴게요", "도움이 되셨길 바랍니다", "언제든 말씀해 주세요" → 하지 않을 일은 말하지 않고, 한 일만 "~했습니다" |
| **AI 말투: 장황한 설명** | 한 일을 다시 요약하는 둘째 문장, "다음과 같습니다:" 뒤 목록 → 결과 한 문장 + 카드 |
| **AI 말투: 확신 흐리기** | "~인 것 같습니다", "~일 수도 있습니다"를 사실 안내에 쓰지 않음. 불확실하면 무엇이 불확실한지 적음: "사진에서 읽은 금액이라 확인이 필요합니다" |
| **불필요한 따옴표·괄호** | "'실행' 버튼을 눌러 주세요" → "실행을 누르세요", "(선택)"·"(필수)"를 문장 안에 넣지 않고 칸 라벨 옆 작게 |
| **기호·이모지** | 안내 문장에 이모지, 느낌표, "→"를 쓰지 않습니다 |

### 2.5 상태·배지 이름

- 배지는 **명사나 짧은 상태어 2~6자**: `진행 중`, `승인`, `반려`, `회수`, `결재 대기`, `사내 처리`, `실행 취소 가능`.
- 한 개념에 한 배지. 같은 상태를 화면마다 다르게 부르지 않습니다(`실행됨`/`실행함` 같은 쌍 금지).
- 색만으로 뜻을 전하지 않습니다. 배지 글이 혼자 읽혀야 합니다.

### 2.6 에이전트 답(모델이 쓰는 문장)

모델이 쓰는 답은 코드로 고정하지 못하지만, 시스템 프롬프트와 고정 안내(라우팅, 확인 요청, 차단 안내)는 이 원칙을 따릅니다.

- 첫 문장에 결과나 답. "네, 확인해 보겠습니다" 같은 여는 말 없음
- 한 일은 "~했습니다", 할 수 없는 일은 이유 한 줄 + 대안 한 줄
- 마크다운 굵게·목록은 값이 셋 이상일 때만
